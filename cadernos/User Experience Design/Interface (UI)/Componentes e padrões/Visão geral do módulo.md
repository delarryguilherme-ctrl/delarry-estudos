# Componentes e padrões

---

Este módulo trata das peças com que uma interface é montada e das soluções que se repetem de produto para produto. Um designer que desenha cada tela do zero gasta tempo, produz inconsistência e obriga o usuário a reaprender o que já sabia em outro app. Quem domina componentes e padrões reaproveita o que já funciona, comunica-se melhor com desenvolvedores e consegue manter um produto coerente mesmo com várias pessoas mexendo nele.

Os cadernos se encadeiam do geral para o específico. Primeiro vem a ideia de padrão de design como solução reutilizável para um problema recorrente. Depois, o Atomic design organiza as peças em níveis, dos menores elementos às páginas. Em seguida, a anatomia e os estados mostram como cada componente é construído e como ele se comporta em cada situação. Os padrões recorrentes juntam componentes em soluções conhecidas, como formulários, navegação e busca. Por fim, a visualização de dados básica aplica o mesmo raciocínio a gráficos e tabelas, para que números virem informação legível.

## Conteúdos

1. [[Design patterns]] — o que é um padrão de design, por que reaproveitar soluções comprovadas e como adaptá-las ao contexto.
2. [[Atomic design]] — a metodologia que organiza a interface em átomos, moléculas, organismos, templates e páginas.
3. [[Anatomia e estados de componentes]] — as partes que formam um componente e os estados que ele precisa prever, como repouso, foco, erro e desativado.
4. [[Padrões recorrentes]] — soluções que aparecem em quase todo produto digital e como escolher entre elas.
5. [[Visualização de dados básica]] — como escolher e desenhar gráficos simples que comuniquem sem confundir.

## Leituras

- Brad Frost — [Atomic Design](https://atomicdesign.bradfrost.com/) (o livro completo online, base do caderno sobre Atomic design e útil para todo o módulo).
- Google — [Material Design 3: componentes](https://m3.material.io/components) (catálogo de componentes com anatomia, estados e orientações de uso).
- Apple — [Human Interface Guidelines: componentes](https://developer.apple.com/design/human-interface-guidelines/components) (outro catálogo oficial, para comparar decisões entre plataformas).
- Shopify — [Polaris: componentes](https://polaris.shopify.com/components) (exemplo de design system real, com documentação aberta de cada peça).
- Anders Toxboe — [UI-Patterns](https://ui-patterns.com/) (biblioteca de padrões de interface organizada por problema).
- Cole Nussbaumer Knaflic — [Storytelling with Data](https://www.storytellingwithdata.com/books) (livro que sustenta o caderno de visualização de dados).
